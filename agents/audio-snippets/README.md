# Audio Snippets

A word-timed transcript of an audio or video file, plus the cut points for the quotes or the question you give it, and optionally the cut clips. Capability `audio.transcript.snippets.v1`.

Status: PROPOSED (built, not deployed). Since 2026-10-13. The service is built and its tests run the real ffmpeg and, where it is installed, the real speech model. It has no registry record and no advert yet, and no job has run. `specs/audio-snippets.md` at the repository root is the specification; this page and the manifest describe the code.

The service sits behind the template runtime (`vector-agent-template`, `CAPABILITY_KIND=custom`). The runtime holds the supplier key, claims the escrow of the hirer and posts the job to this service as the body of `POST /`. The service fetches the media or decodes it from the request, reads its type from its first bytes, probes it with `ffprobe` and decodes it to 16 kHz mono WAV with `ffmpeg`, in a private temporary directory. It transcribes the audio word by word with faster-whisper on the CPU, in a Python process of its own for each job, finds the quotes, the question and the ranges of the request in the transcript, cuts the clips when they are asked for, and answers with the result, which the runtime hashes into the one receipt it signs. The service holds no key and posts nothing.

`agent.json.template` is the manifest with placeholders. The service renders the real manifest from its environment when it starts and serves those bytes at `GET /agent.json`. It never serves the template itself. `<OPERATOR_CONTACT>`, `<AGENT_DID>`, `<SUPPLIER_PKH>` and `<SUPPLIER_PUB_KEY_HEX>` in the template stand for the values in the table below.

## Run it

The service needs `ffmpeg` and `ffprobe` on the path, and a Python of 3.9 or later with the speech model: `asr/requirements.txt` pins faster-whisper 1.2.1 and ctranslate2 4.8.2, and `asr/fetch_model.py` fetches the files of the model at a pinned revision and checks them. The image has all of it; on another machine:

```bash
pnpm install
cd agents/audio-snippets
python3 -m pip install -r asr/requirements.txt
python3 -I asr/fetch_model.py base .models/base                          # about 150 MB from huggingface.co, once
export SERVICE_AUTH_HEADER="Bearer $(openssl rand -hex 32)"           # the token a caller must send, generated by openssl
OPERATOR_CONTACT=ops@example.test SUPPLIER_PKH=<56 hex> SUPPLIER_PUB_KEY_HEX=<64 hex> WHISPER_MODEL_DIR=.models/base PORT=9093 pnpm start
```

It stops at start, with the variable named, when `OPERATOR_CONTACT`, `SUPPLIER_PKH`, `SUPPLIER_PUB_KEY_HEX` or `SERVICE_AUTH_HEADER` is not set, when a setting is not well formed, when `SUPPLIER_PUB_KEY_HEX` is not the public key of `SUPPLIER_PKH`, or when `ADVERT_MAX_PROCESSING_MS` is below 25 min. It also asks `ffprobe` and `ffmpeg` for their version and the worker of the speech model to check itself (faster-whisper imports, and the files of the model are there) before it listens, and does not start if one of them fails, so that a service without them cannot answer `/healthz` ok and then fail every job.

A secret in the wrong line of an env file is the mistake the start guards against. The service token is looked for in every other setting the service reads, whole or by its credential (the part after `Bearer `), each when it is 16 characters or more, and found there it stops the start, naming the variable and not showing the token. So it is in no message, no log line and no answer, and the manifest is searched for it once more before the service listens. No message of the service shows a setting that is hex-shaped or long, only its length. `SUPPLIER_PUB_KEY_HEX` must be the public key of `SUPPLIER_PKH`, which catches a private key put in its line.

## Routes

| Route | Answer |
|---|---|
| `GET /healthz` | `{"ok":true}`, or 503 `{"ok":false,"reason":"low_disk"}` when the last check found less than 268435456 bytes (256 MiB) free in the temporary directory. The check is made at most once a minute, in the background: a request is answered from the last one and never waits. Before the first check has answered it is `ok`. |
| `GET /agent.json` | the manifest, the bytes `JSON.stringify` gives |
| `POST /` | the wire message and nothing else, with the `authorization` header of the runtime. Without it, 401 |
| any other route | 404 `{"error":"not_found"}` |

`GET /healthz` and `GET /agent.json` are matched on their path, whatever the query string, and a `HEAD` of either gets the headers of the `GET`, its `content-length` included, and no body.

The body of `POST /` is the wire message: a one-element array whose `content` is the request JSON as a string, and whose `role` is `user`. It is read up to 1000000 bytes. The request JSON is `{ "source": ..., "language": "en", "query": "...", "quotes": [...], "ranges": [...], "return_clips": false, "clip_format": "mp3" }`, with at least one of `query`, `quotes` and `ranges`; the manifest publishes its schema under `interface.request_schema`, and what a schema cannot say under `interface.notes`. The answer to a job is `JSON.stringify(result)`, serialised once, exactly the bytes the runtime hashes.

`POST /` requires the `authorization` header to be exactly the value of `SERVICE_AUTH_HEADER`, the value the template runtime sends with every call to a custom service. The runtime and the service read it from the same env file, and neither blanks it. A call without the header, or with another value, gets 401 `{"error":"unauthorized"}`, with no detail, before the body is read and before the job slot is taken. The two values are compared in constant time (`crypto.timingSafeEqual` on their sha256 digests), and a refusal is logged once a minute at most, with a count and nothing the caller sent. `GET /healthz` and `GET /agent.json` need no header: the image's health check sends none, and the manifest is public.

One job runs at a time: the speech model takes the CPU of the container. A second job that arrives while one runs gets 409 `{"error":"busy"}` and nothing is started. A job has its own deadline, 1320000 ms after its request arrives, 60 s inside the runtime's `SERVICE_TIMEOUT_MS` of 1380000. The speech recognition gets the smaller of 900000 ms and the time the job has left, 60000 ms less of it when clips are asked for, and is not started when that comes to under 30000 ms.

While a job runs, the server writes an interim `102 Processing` line every 60 s to a client that speaks HTTP/1.1, ahead of the answer, which is the same 200 with the same body as it would be without them. The reason is that the runtime's fetch gives up after 300 s of silence (the headers timeout of undici, behind fetch) and a job of 10 min of audio can take longer: without the lines the runtime would report `service_unreachable` at the five minute mark while the service goes on with the job. The lines stop when the job ends.

## Errors

A refusal is `{"error": "<code>", "message": "<words>"}` with the status in the table. A failure on the service's side (`asr_failed`, `clip_failed` and `low_disk`) gets a fixed message, `The service could not do this job (<code>). The operator's log has the detail.`, because the runtime copies the first 200 characters of a failure to the buyer and the detail is the operator's: the whole message is in the log. `shutting_down` says in words that the service is stopping. Anything else is 500 `{"error":"internal"}` with no detail; the cause is in the log, by message only. The 401 has no message at all.

| Status | Codes |
|---|---|
| 400, the message | `bad_wire` (not the one-element message array), `request_too_large` (over 1000000 bytes) |
| 400, the request | `bad_json`, `bad_shape`, `base64_too_large`, `language_bad`, `language_unsupported`, `nothing_to_find`, `range_bad` |
| 401, the caller | `unauthorized` (the call has no authorization header, or one that is not the token of the service) |
| 422, the media | `source_fetch_failed`, `source_too_large`, `source_unsupported`, `source_mime_mismatch`, `media_unreadable`, `media_no_audio`, `media_too_long`, `range_out_of_media` |
| 422, the job | `deadline` (the job ran out of its time) |
| 503, the service cannot take a job now | `low_disk`, and `shutting_down` (the service is stopping) |
| 500, the service | `asr_failed` (the speech model failed or wrote no transcript), `clip_failed` (ffmpeg could not cut a clip), and `internal` |

Every refusal locks nothing of the service's: it holds no key and posts nothing. The runtime fails the job, and the hirer reclaims the escrow after its `deliver_by`. The 400s, the 401 and the 422s of the media come before the speech model runs.

## The speech model

`asr/worker.py` runs one job: it reads one JSON request on stdin, runs faster-whisper on the WAV it names, writes one JSON answer on stdout and exits. `src/asr.ts` starts it with an argument list, as `python3 -I <worker>` (Python's isolated mode), bounds it in time and in output, logs what it writes on stderr, flat and at most 20 lines, and holds what it writes on stdout to the contract. The model runs on the CPU with `compute_type` int8, `WHISPER_THREADS` threads, word timestamps on and voice-activity filtering off, `beam_size` 5 and `temperature` 0.0 alone, so that the same audio gives the same transcript. The language of the request is passed through; `auto` lets the model detect it from the first 30 s, and the result says which. The result names the model `faster-whisper-<size>-int8`; the receipt names `audio-snippets-v1`.

## Matching

A quote is matched over the stream of words: the text is normalised (Unicode NFKC, lower case, the apostrophes dropped, any other character that is no letter, mark or digit a space), and the quote of n words is compared with every window of the transcript of 0.7 n rounded down to 1.3 n rounded up words (at least one) by the ratio 1 - levenshtein / longer length. The best window is the match, the earlier on a tie, then the shorter; at or above 0.55 the quote is a match, and under it the quote is listed in `unmatched` with its best score. A question is matched by keyword overlap at segment level (`match_method` `keyword`): the Jaccard of its content words and those of each segment, at or above 0.2, at most 3 segments, adjacent ones merged. A range is taken as given and scores 1; its text is the words between its ends, once they have snapped to word boundaries. A match is cut at the boundaries of its first and last words, an end inside a word moves out to that word's boundary, and 150 ms of padding is added on each side, within the media. Every number of the result is rounded to 3 decimals.

Clips are cut from the decoded audio, one for each match, as MP3 at 64 kbps or as WAV. Each carries its sha256 and its size; its bytes, as base64, only while the total of the clips that carry them stays at or under 2000000 bytes, and `clips_truncated` says when one did not.

## Stopping

On SIGTERM (`docker stop` sends it) or SIGINT the service takes no new job and no new connection, and waits up to 300 s for the job that is running to end. The wait is on the job itself, so a caller that hangs up does not cut it short. A job that ends in time is answered, if its caller is still there, and the service exits 0. One still running after 300 s is abandoned: its connection is closed, the log says so, and the service exits 1. The container is killed when its grace period ends, so `stop_grace_period` in the compose file is 330 s: the 300 s of the wait and 30 s more, for the log line and the exit code of a job the service had to abandon. A second signal ends the process at once.

## Manifest

`agent.json.template` is the JSON that `manifestFromEnv` prints with the four placeholders. A test keeps the two equal, byte for byte, so change the template by changing `manifestFromEnv` and regenerating it: `pnpm --filter @vsa/audio-snippets template`.

| Variable | Use | Default |
|---|---|---|
| `OPERATOR_CONTACT` | `operator.contact` | none. Required: the service stops at start without it |
| `SUPPLIER_PKH` | `identity.controller_pkh` and `keys.supplier_pkh`, 56 hex characters | none. Required |
| `SERVICE_AUTH_HEADER` | the `authorization` header the runtime sends with every call, which `POST /` requires: `Bearer ` and 64 hex characters, made with `openssl rand -hex 32`. Never published, never logged | none. Required: the service stops at start without it |
| `SUPPLIER_PUB_KEY_HEX` | `keys.pub_key_hex`, 64 hex characters, the public key of `SUPPLIER_PKH`: the service stops at start unless its key hash is `SUPPLIER_PKH` | none. Required: the service stops at start without it |
| `AGENT_DID` | `identity.did` | empty |
| `AGENT_VERSION` | `version` | `0.1.0` |
| `ADVERT_PRICE_LOVELACE` | `terms.price_lovelace` | `2000000` |
| `ADVERT_MAX_PROCESSING_MS` | `terms.max_processing_ms`; at least 1500000, because the deadline of a job assumes the 25 min window | `1500000` |
| `AGENT_STATUS_CHIP` | `status.chip`, in lower case | `proposed` |
| `AGENT_STATUS_SINCE` | `status.since`, as YYYY-MM-DD | `2026-10-13` |
| `ADVERT_EXPLORER_URL` | `links.explorer_advert` | empty |
| `WHISPER_MODEL` | the size of the speech model, `base` or `small`; the second gap of the manifest names it, and the image sets it to the size it was built with | `base` |
| `WHISPER_THREADS` | the threads of the speech model, 1 to 64 | `4` |
| `WHISPER_MODEL_DIR` | the folder of the files of the model | `/app/asr/models/<size>` |
| `ASR_PYTHON` | the Python that runs the worker | `python3` |
| `ASR_WORKER` | the worker; the image sets `/app/asr/worker.py` | `asr/worker.py` of this folder |
| `PORT`, `HOST` | where the service listens | `9093`, `0.0.0.0` |

Numbers (and `PORT`) must be non-negative integers. `AGENT_STATUS_CHIP` must be live, deployed or proposed, in any case. A value that breaks a rule stops the service at start, and the error names the variable. The advert `detail_uri` points at `GET /agent.json` and its `detail_hash` is the sha256 of the bytes served there. Adverts are immutable, so a changed manifest means a retired advert and a new one.

## Tests

```bash
pnpm --filter @vsa/audio-snippets test
```

The tests need no network and no key. The tests of the media and of the clips run when `ffmpeg` and `ffprobe` are on the path, and skip otherwise. The contract of the worker is tested in Python with a stub of the model (`asr/test_worker.py`, Python 3.9 or later). The tests of the real model run when faster-whisper imports in `ASR_PYTHON` (default `python3`) and the files of the model are in `WHISPER_MODEL_DIR` (default `.models/base` of this folder, where `asr/fetch_model.py` puts them): they transcribe the 25 s of `test/fixtures/speech-20s.mp3`, a public-domain LibriVox recording, and hold the times of one sentence to those of the pauses around it. `REQUIRE_ASR=1`, which CI sets, makes a missing tool, Python, faster-whisper or model fail its test instead of skipping it.

## Image

`Dockerfile` builds the service image in three stages. The build context is the repository root, because the image installs the workspace from the lockfile: `docker build -f agents/audio-snippets/Dockerfile -t vsa/audio-snippets:dev .`. The second stage installs `asr/requirements.txt` in a venv and fetches the model of the build argument `WHISPER_MODEL` (`base` by default) to `/app/asr/models/<size>`; the image fetches nothing at run time. The image runs as the `node` user under `tini`, listens on 9093 and answers `/healthz` for its health check, with `python3` (the venv first on the path), `ffmpeg` and `ffprobe`. It has no volume. The memory limit is set where the container is run; the compose file gives it 3072m.
